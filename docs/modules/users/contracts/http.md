# Users — HTTP

Auth: Bearer JWT. Envelope `{ data, meta }`.

| Método | Path                               | Body                                                             | Notas                                                                                                                                                                                                                                                                                            |
| ------ | ---------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GET    | `/api/users/me`                    | —                                                                | Perfil + preferences mergeadas + `userModules` + `lastSeenReleaseVersion` (nullable)                                                                                                                                                                                                             |
| PATCH  | `/api/users/me`                    | `UpdateProfileDto` parcial                                       | Email read-only; preferences merge                                                                                                                                                                                                                                                               |
| DELETE | `/api/users/me`                    | —                                                                | Cascade app data + outbox Auth; 404 si no hay fila `users`                                                                                                                                                                                                                                       |
| GET    | `/api/users/me/data/branches`      | —                                                                | Ramas de datos agrupadas por app, con su conteo y lo que arrastran (`includes` con conteo)                                                                                                                                                                                                       |
| POST   | `/api/users/me/data/wipe`          | `{ branches: string[], expectedCounts?, balanceInstitutionId? }` | Vaciado por ramas sin cerrar la cuenta. 200 con `requestedBranches`, `appliedBranches` y `counts`. Auto-expande lo que arrastra cada rama. 400 rama vacía, desconocida o de una app apagada; 409 si algún conteo cambió respecto de `expectedCounts` (responde `details.counts` y no borra nada) |
| PATCH  | `/api/users/me/modules/:slug`      | `{ isEnabled?, config? }`                                        | Slug de un módulo registrado: `finance` \| `agenda` \| `projects` \| `health` \| `ai`. Un slug desconocido o retirado como `subscriptions` responde 400                                                                                                                                          |
| PATCH  | `/api/users/me/release-notes-seen` | `{ version }` (X.Y.Z)                                            | Guarda la última versión de Novedades vista en `users.last_seen_release_version`. 400 si el formato no es X.Y.Z; 404 sin fila `users`                                                                                                                                                            |

`preferences` no guarda config de módulo; eso va en `user_modules.config`.

Para `slug=ai`, el descriptor de Intelligence valida `config.email.reviewConfidenceThreshold` como número entre `0` y `1` (predeterminado `0.7`) y `config.email.acceptVerifiedSenders` como booleano (predeterminado `false`). El descriptor de Finance valida `reminders.cardDueDaysBefore` y `subscriptions.reminderDaysBefore` en sus rangos; un valor fuera de rango responde 400. Users persiste el resultado sin interpretar los campos.

`preferences.regional` agrupa las preferencias de región. `weekStartsOn` acepta `0` (domingo), `1` (lunes), `6` (sábado) o `null`; `null` resuelve el primer día desde `users.locale` (`Intl.Locale.weekInfo`; lunes solo si el motor no expone `weekInfo`). `PATCH /users/me` responde 400 para cualquier otro valor y para un `locale` que no sea una etiqueta BCP-47 válida; `GET /users/me` devuelve lo guardado, sin resolver. Un locale inválido o un primer día fuera de `0`/`1`/`6` en datos viejos hace fallar la lectura en lugar de adivinar. Los valores `weekStartsOn` que quedaron en `user_modules.config` de Finanzas y Agenda se copian al perfil con `pnpm db:backfill-week-starts-on` (`--dry-run` para revisar).

La fila `users` la crea un trigger de Supabase al signup (checklist web/back). Sin fila, `GET /users/me` falla.

Evidencia: `users.controller.ts`, `users.service.spec.ts`, `test/users.e2e-spec.ts`.

Wipe: `WipeUserDataUseCase` consulta el **registro de ramas** que declara cada app (`DataBranchDescriptor` en `@personal-os/users`), expande lo que arrastran las pedidas, comprueba los conteos que el usuario vio, delega en el port `USER_DATA_WIPE_DOMAINS` (adapter en `apps/api/src/user-data-wipe`, que reparte entre Finanzas, Asistente IA, Notificaciones y Configuración) y emite un único `user.data.wiped` con las ramas aplicadas. Idempotente: ramas ya vacías → `counts` en 0. Una app nueva añade sus ramas sin tocar el orquestador.

Ramas de Finanzas: `finance.reconciliations`, `finance.transactions` (arrastra `finance.reconciliations`), `finance.balances`, `finance.cards` (solo crédito), `finance.debitCards`, `finance.accountImports`, `finance.accounts`, `finance.institutions`, `finance.subscriptions`, `finance.recurring`, `finance.merchants`, `finance.emailMessages`, `finance.statements`, `finance.loans`, `finance.savingsGoals`, `finance.receivables`, `finance.budgets`, `finance.categories` (arrastra `finance.budgets`) y `finance.emailConnections`; el detalle de cada una está en `docs/modules/finance/capabilities/data-wipe.md`. Otras apps: `ai.inferences`, `notifications.history`, `notifications.pushTokens` y `settings.defaults`. `ai.inferences` borra la telemetría de inferencia del usuario. Las ramas `finance.*` solo se ofrecen si el usuario tiene la app Finanzas encendida.
