# Contrato HTTP de Knowledge (AI-4)

Estado: `VERIFICADO` en `ai-knowledge.controller.ts` y `test/ai-agent.e2e-spec.ts`. Todas las rutas requieren JWT y usan el envelope HTTP estándar `{ data, meta }`. Fechas: ISO 8601. Secuencias `BigInt`: strings decimales en exportación y respuesta de rebuild.

| Método | Ruta                                                    | Rol                      | Request                 | HTTP | `data` en éxito                                                                                                                                                         |
| ------ | ------------------------------------------------------- | ------------------------ | ----------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/intelligence/knowledge`                           | USER, CONTRIBUTOR, ADMIN | —                       | 200  | `{ personal: AiKnowledge[], global: AiKnowledge[] }`; `personal` filtra `userId`, `global` contiene solo `STABLE`                                                       |
| GET    | `/api/intelligence/knowledge/admin/queue`               | ADMIN                    | —                       | 200  | `AiKnowledge[]` de alcance GLOBAL, incluidos `REVIEW_REQUIRED` y `BLOCKED`                                                                                              |
| POST   | `/api/intelligence/knowledge/admin/rebuild`             | ADMIN                    | sin body                | 201  | `{ runId, observationSequence, verificationSequence, consentRevision, items }`                                                                                          |
| POST   | `/api/intelligence/knowledge/admin/:knowledgeId/revert` | ADMIN                    | sin body                | 201  | `AiKnowledge` GLOBAL con `state: BLOCKED`; 404 si no existe                                                                                                             |
| GET    | `/api/intelligence/knowledge/me/export`                 | USER, CONTRIBUTOR, ADMIN | —                       | 200  | JSON con `exportedAt`, `connection`, `messages`, `datasetItems`, `runs`, `observations`, `verifications`, `knowledge`, `consent`, `settings`, `inferences` de la cuenta |
| DELETE | `/api/intelligence/knowledge/me`                        | USER, CONTRIBUTOR, ADMIN | `{ "confirmed": true }` | 200  | `{ deleted: true, deletedMessages, detachedVerifications, detachedObservations }`                                                                                       |

`AiKnowledge` incluye `id`, `scope`, `userId`, `knowledgeType`, `knowledgeKey`, `state`, `payload`, `messagesSeen`, `rejectedMessages`, `distinctUsers`, `humanVerifiedCount`, `promotedBy`, versiones y fechas. `payload` de GLOBAL es `{ label: { relevance?, semanticType?, routes?, transaction?: { kind } } }`; nunca se devuelve una lista de usuarios contribuyentes. El endpoint admin devuelve datos estructurales GLOBAL, sin evidencia personal.

La exportación incluye cuerpo canónico y crudo aún retenido de los mensajes propios. `connection` no contiene `accessTokenEncrypted` ni `refreshTokenEncrypted`. El borrado requiere `confirmed: true`; `false` o campos inválidos dan 400. Las rutas ADMIN dan 403 para USER/CONTRIBUTOR. La ausencia de JWT da 401.

El reinicio ya existente `POST /api/intelligence/email/reset` mantiene `{ "confirmed": true }` y devuelve `{ connected: true, deletedMessages }` cuando hay conexión; ahora anonimiza la evidencia antes de vaciar el corpus, conserva OAuth y reconstruye GLOBAL. `GET /api/intelligence/runs` añade `consentRevision`, `reproductionStatus` (`COMPLETE` o `INCOMPLETE`) y `missingEvidence` (`observations`, `humanVerifications` cuando se retiró evidencia).
